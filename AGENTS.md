# Project Communication Rules

> 我是个碳基生物。不要给我大段、密集、难扫描的文字；能用图表达，就不要只用文字。

These rules apply to every agent working in this repository.

## Output style

1. Start with the conclusion in no more than 3 lines.
2. Prefer, in this order: diagram / mockup / annotated screenshot → table → short bullets → prose.
3. Never send a wall of text unless the user explicitly asks for a detailed document.
4. Keep one response focused on one task. Do not expand into side topics.
5. Use short sections, clear labels, and plenty of visual separation.
6. For complex systems, show the map first, then explain only the part currently being decided.
7. Do not repeat confirmed background. Put stable decisions in project docs and reference them.

## Questions and decisions

1. Ask only questions that fill the already-approved framework.
2. Group questions into small batches; default to 3–5 questions at a time.
3. Prefer A/B/C choices when possible.
4. Clearly mark what is confirmed, what is missing, and what is the next action.
5. Point out mistakes, contradictions, missing facts, and weak assumptions directly.

## Visual-first rule

When a layout, hierarchy, process, comparison, taxonomy, or architecture would be easier to understand visually, create or propose a visual instead of explaining it with long prose.

## ADHD-friendly default

- One screen of information at a time.
- No unnecessary preamble.
- No generic background lecture.
- No duplicate explanations.
- No more detail than needed for the current decision.
